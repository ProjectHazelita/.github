# Contributing to Project Hazelita

Thank you for taking the time to contribute to Project Hazelita. 🪼

Contributions do not have to begin with a pull request.

A useful bug report, a thoughtful question, a documentation improvement, a translation, a design suggestion, a review, or a small idea shared at the right moment can all make a project better.

If you are new here, you are welcome to start small.

## Before you begin

Different Project Hazelita repositories may use different languages, tools, workflows, and release processes.

If the repository contains its own `CONTRIBUTING.md`, development documentation, or project-specific instructions, please follow those first.

This document describes the default contribution practices shared across Project Hazelita projects.

All contributors are also expected to follow our [Code of Conduct](./CODE_OF_CONDUCT.md) and the [Project Hazelita Community Guidelines](https://github.com/ProjectHazelita/community-guidelines).

## Issues

Before opening a new issue, please search existing issues to see whether the same topic has already been reported or discussed.

When reporting a bug, include enough information for someone else to understand and reproduce the problem whenever possible.

Useful details may include:

- what happened;
- what you expected to happen;
- steps to reproduce the issue;
- the affected version or commit;
- your operating system or environment;
- relevant logs, screenshots, or error messages.

Please remove passwords, tokens, private data, and other sensitive information before posting logs or screenshots.

### Feature requests

Feature requests are welcome.

A good feature request usually starts with the problem you are trying to solve rather than only describing a particular implementation.

For larger changes, architectural changes, or features that may significantly affect existing behavior, please open an issue or discussion before investing substantial time in implementation.

This helps contributors and maintainers explore the problem together before anyone disappears into a cave and returns three weeks later with a 14,000-line pull request. 😭

## Pull requests

Pull requests should, whenever practical, focus on one clear purpose.

Before submitting a pull request:

- make sure the project builds or runs successfully in your environment;
- run the relevant tests, linters, and formatters when available;
- update documentation when the change affects documented behavior;
- avoid unrelated formatting or refactoring changes;
- explain what the change does and why it is needed.

Small pull requests are often easier to review, understand, and maintain than large ones.

Do not worry about making your first contribution perfect.

Review is part of collaboration, not an exam.

## Commit history

Individual repositories may define their own commit conventions.

When no project-specific convention exists, prefer commit messages that briefly explain the purpose of the change.

A clean history is helpful, but contributors are not expected to spend unreasonable amounts of time polishing local commit history before opening a pull request.

Maintainers may squash or otherwise reorganize commits when merging.

## Reviews

Code review is a conversation about the contribution, not a judgment of the contributor.

When reviewing someone else's work:

- explain the reason behind requested changes;
- distinguish required changes from suggestions or personal preferences;
- be patient with contributors who are unfamiliar with the project;
- assume good faith where reasonable;
- focus criticism on the work, not the person.

When receiving review feedback, questions and disagreement are welcome.

It is completely acceptable to ask why a change is being requested.

## AI-assisted contributions

Project Hazelita welcomes the responsible use of AI-assisted development tools.

AI tools may be used for tasks such as programming, debugging, documentation, translation, research, or exploring possible implementations.

However, the person submitting a contribution remains responsible for the contribution itself.

Before submitting AI-assisted work, please make a reasonable effort to:

- understand what the submitted code or text does;
- verify that it actually solves the intended problem;
- test generated code where appropriate;
- review generated content for incorrect assumptions or fabricated information;
- check that the contribution does not unintentionally include secrets, private data, or incompatible copyrighted material;
- be able to discuss and revise the contribution during review.

Please do not submit large amounts of unreviewed generated content and expect maintainers to validate it on your behalf.

Using a tool is fine.

Outsourcing responsibility to the tool is not.

If AI assistance materially affects a contribution and mentioning it would help reviewers understand how the work was produced or verified, contributors are welcome to disclose that context in the pull request.

## Security issues

Please **do not report security vulnerabilities through public issues**.

Refer to the repository's `SECURITY.md` or the organization-wide security policy for the appropriate reporting method.

If you are unsure whether something is a security issue, it is usually better to report it privately first.

## Licensing

By contributing to a Project Hazelita repository, you agree that your contribution may be distributed under the license used by that repository unless explicitly stated otherwise.

Please only contribute material that you have the right to contribute.

If a contribution includes code, assets, text, or other material derived from third-party sources, make sure its license and attribution requirements are compatible with the project.

## Not sure where to start?

That is completely okay.

You can browse open issues, look for documentation that could be clearer, ask questions, or join the wider Project Hazelita community.

You do not need to already know the codebase to belong in the conversation.

Many good contributions begin with someone saying:

> “I noticed something, but I'm not sure what the right solution is yet.”

That is a perfectly good place to begin.

Thank you for helping Project Hazelita grow — one issue, patch, idea, review, and conversation at a time. 🌱
