# Getting Help

Welcome to Project Hazelita. If you run into a problem, the best way to ask for help depends on what you are working on.

This document is the support guide used by default across Project Hazelita projects. If a specific project provides its own documentation, support channels, or `SUPPORT.md`, follow that project's own instructions first.

## Where Should I Go?

| What you are dealing with | Recommended destination |
| --- | --- |
| A bug in the software | The Issue tracker of the corresponding project |
| A feature suggestion | An Issue or Discussion |
| You don't know how to use a project | README, project documentation, Discussion, or the Project Hazelita community |
| You want to develop or contribute content | [`CONTRIBUTING-en.md`](./CONTRIBUTING-en.md) |
| You found a security vulnerability | [`SECURITY-en.md`](./SECURITY-en.md) |
| Harassment, discrimination, conflict between members, or other community issues | The channels specified in the [Project Hazelita Community Guidelines](https://github.com/ProjectHazelita/community-guidelines) |
| You just want to talk about projects, technology, or anything else interesting | The Project Hazelita community |

## Bugs

If you believe you have found a bug in a project, please open an Issue in the corresponding repository.

Before you do, we recommend:

- A quick search of existing Issues to see whether someone has already reported it;
- Explaining what actually happened and what you expected to happen instead;
- Providing reproduction steps, version, and runtime environment where possible;
- Attaching helpful logs, screenshots, or error messages.

For more complete advice on contributing and reporting bugs, see [`CONTRIBUTING-en.md`](./CONTRIBUTING-en.md). If the issue may have security implications, do not open a public Issue; report it privately by following [`SECURITY-en.md`](./SECURITY-en.md) instead.

## Feature Suggestions

Feature suggestions can be raised through the corresponding project's Issues or Discussions.

For ideas that are larger in scope and may affect the architecture or existing behavior, we recommend discussing the requirements and design first before investing a large amount of implementation work.

## Usage Questions

If you don't know how to use a project, we recommend checking the project's README, project documentation, and existing Issues or Discussions in that order. If you still can't find the answer, you can ask in the project's Discussions, or come to the Project Hazelita community and talk with everyone there.

If a usage question actually reveals missing documentation, unexpected behavior, or a software defect, you are also welcome to open an Issue.

## The Project Hazelita Community

If a problem doesn't belong to just one repository, or you simply want to discuss technology, projects, learning, creative work, and everyday topics, you are welcome to join the Project Hazelita community.

Our community spaces currently include:

- 🏙️ **Hazelita Plaza** — a QQ group chat;
- 🌿 **Hazelita Commons** — a Discord server;
- 📡 **Hazelita Relay** — a Telegram group.

You can get the currently valid invitation links from the [Project Hazelita GitHub Profile](https://github.com/ProjectHazelita). When participating in the community, please follow the [Project Hazelita Community Guidelines](https://github.com/ProjectHazelita/community-guidelines).

## Community Conduct and Moderation Issues

If you need to report harassment, discrimination, conflict between members, privacy concerns, moderation conduct, or anything else that may violate the Project Hazelita Community Guidelines, please use the channels specified in the guidelines.

When personal information or sensitive incidents are involved, please avoid submitting reports through public GitHub Issues, Discussions, or other public channels.

## A Project's Own Rules Come First

Different Project Hazelita projects may maintain their own documentation, Issue Templates, Discussions, FAQs, support channels, `CONTRIBUTING.md`, `SECURITY.md`, or `SUPPORT.md`. If a project provides more specific instructions, please seek help in that project's own way first.

## About Response Times

Project Hazelita projects are maintained primarily by community members using their own time and energy. How quickly you get a reply may depend on how active the project is, how complex the issue is, and the maintainers' current schedules. Not receiving a reply immediately does not necessarily mean your issue is being ignored, so please avoid repeatedly pinging maintainers, opening duplicate Issues, or sending the same content across multiple channels just to hurry along a response.
